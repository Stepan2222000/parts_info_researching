# Источники и доказательства

1. Используй только сохраненные Exa JSON. В интернет, fetch, web search, MCP, браузер и другие файлы не ходи.
2. Используй только источники, где явно есть входной артикул или его нормализованный OEM-вариант. Похожие номера без точного совпадения игнорируй.
3. Не придумывай данные. Если Exa не подтверждает поле, ставь null, пустую строку, пустой массив или пустой объект по схеме.

# Формат результата

4. Итоговый JSON должен быть валидным и строго по схеме. Лишние поля не добавляй. Текстовые поля заполняй и на русском (name, description, evidence), и на английском там, где схема просит: name_en, description_en — те же name/description на английском. Английский ОБЯЗАТЕЛЕН: при непустом name заполни name_en, при непустом description — description_en (то же для компонентов kit_contents). Английский кладётся в *_en, а не в скобки русского имени.
4a. name / name_en — КОРОТКИЕ. Из них собирается title фида «<арт1> / <арт2> <name>» с жёстким лимитом 50 символов; при превышении ран ОТКЛОНЯЕТСЯ. Два артикула с пробелами съедают ~22 символа, поэтому на само имя остаётся ~25 — держись этого и для name, и для name_en. Пиши ТОЛЬКО тип детали + отличительную спеку (размер/шаг/вариант): «Форсунка топливная» / «Fuel injector», «Винт гребной 12.5x19P RH» / «Propeller 12.5x19P RH». НЕ включай бренд (он в brand_oem), НЕ включай модель/двигатель/линейку (она в model), без «OEM», маркетинга и длинных расшифровок. Идентифицирующую спеку винта (размер/шаг/вращение) НЕ выкидывай — ужимай формулировку, пока не влезет. Все подробности (материал, назначение) — в description/description_en.
5. В каждом article, article_low_confidence и irrelevant нужны source_url и evidence на русском. Для low_confidence нужен why_low_confidence. Для irrelevant нужен why_irrelevant.
5a. description / description_en — кратко ЧТО это за деталь, её НАЗНАЧЕНИЕ/функция и где применяется (узел, тип техники). 1–2 предложения, без воды и маркетинга. НЕ пиши в описании кросс-/замен-номера, «заменён номером X» / «replaces X», артикулы, SKU и цены — они уже в numbers/us_prices.
5b. us_prices — розничные цены за ОРИГИНАЛ на американских магазинах по входному артикулу. Для каждого магазина бери ТЕКУЩУЮ цену продажи (Price/Now) именно нашего номера (у ритейлеров бывает с префиксом 26-/710-), товар в наличии; НЕ MSRP/зачёркнутую, НЕ "you save", НЕ порог доставки (over $99/$100), НЕ баллы, НЕ цену другого/substitute товара, НЕ aftermarket. site = домен магазина, url = ссылка на товар, article = наш номер, currency как на странице. Нет валидной цены в источниках — us_prices=[].

# OEM и номерные поля

6. Номерные поля только для OEM. Aftermarket-бренды и SKU продавцов не пиши в article, article_low_confidence или irrelevant. Из таких источников можно взять только явно указанный OEM-номер.
7. numbers.article содержит только подтвержденные OEM-кроссы и обязательно включает входной task_part_number с source_url и evidence. Сначала новые/актуальные номера, потом старые; task_part_number ставь на его реальное место в этой цепочке. Поля type и confidence не добавляй.
8. numbers.article_low_confidence содержит только возможные OEM-кроссы, которым не хватает доказательств. Не клади туда aftermarket, SKU продавцов и дубли после нормализации.
9. numbers.irrelevant содержит только явно отброшенные OEM-похожие номера другой OEM-детали. Aftermarket и SKU продавцов туда не переноси.
9a. Каждый OEM-номер попадает РОВНО в один массив — numbers.article, либо numbers.article_low_confidence, либо numbers.irrelevant — и никогда в два сразу. В частности, номер не может одновременно быть в article (подтверждённый кросс) и в irrelevant (чужая деталь): подтверждён — только в article; отброшен как чужая деталь — только в irrelevant; не уверен — article_low_confidence. Держи это и при дозаполнении: переклассифицируя номер, удаляй его из прежнего массива.

# Mercury / Quicksilver

10. Mercury, MerCruiser, Quicksilver и Mariner считай OEM-брендом Mercury Marine.
11. Для Mercury/MerCruiser/Quicksilver/Mariner ВСЕГДА убирай ведущий групповой префикс (1-3 цифры до первого дефиса) из OEM-номера и в numbers.article клади ТОЛЬКО нормализованную форму без префикса. Такой префикс (например 35-, 87-, 10-) — это код категории каталога, а НЕ часть номера. Примеры: 35-879884T -> 879884T; 87-892150Q02 -> 892150Q02; 35-898101T68 -> 898101T68. Правило действует и тогда, когда префиксная форма встречается одна, без «голого» номера рядом. Если после нормализации номер совпал с уже имеющимся (в том числе со входным task_part_number) — это дубль, отдельной строкой его НЕ добавляй.

# Нормализация SKU

12. Суффиксы продавца/бренда не дублируй, например 24677251-VP -> 24677251.

# Наборы и комплекты

13. is_kit всегда boolean. Ставь true, если входной артикул сам явно назван kit, set, комплект, набор, repair kit, tune-up kit, anode kit или похожим полным набором. Иначе ставь false.
14. is_kit = true не означает, что состав уже полностью найден: если состав неизвестен, kit_contents может быть пустым или частичным.
15. kit_contents заполняй только если is_kit = true.
16. Никогда не добавляй входной артикул или любой артикул из numbers.article как компонент самого себя в kit_contents. numbers.article — это номера самой исследуемой детали или набора, а не его компонентов.
17. Если входной артикул одиночная деталь, а рядом продается другая деталь, kit_contents оставь пустым.
18. Если is_kit = false, kit_contents должен быть пустым объектом.
19. Если артикул компонента набора неизвестен, ставь article: null. Не ставь пустую строку "".
19a. Вложенные наборы (kit-in-kit): если компонент набора САМ является набором/kit/set со своим номером (например, внутри большого ремкомплекта лежит набор шестерён) — включи его в kit_contents одним компонентом с is_kit=true и его номером. Состав такого под-набора в этом ране НЕ раскрывай и его внутренности НЕ перечисляй отдельными компонентами: отдельными строками идут только детали, лежащие в наборе ПОМИМО под-набора (иначе получится двойной учёт). Компонент — одиночная деталь → is_kit=false; не удалось выяснить → is_kit=null.
20. part_of_kits используй, когда входной артикул входит в другой набор или связку. Указывай БЛИЖАЙШЕГО известного родителя: если деталь входит в большой набор только через под-набор — пиши под-набор, а не большой набор. Если номера набора нет, ставь kit_article: null и объясняй это в evidence.
21. Запись вида "деталь A + деталь B" не делает входной артикул набором. Это part_of_kits, если только источник прямо не говорит, что входной артикул сам является номером набора.
21b. Набор может быть кроссом другого набора ТОЛЬКО при эквивалентном составе (прямая полная замена, supersession всего набора). Если один набор входит в состав другого, их состав различается или номера предназначены для разных серийных диапазонов/годов — это НЕ кросс и НЕ supersession: связь выражай через kit_contents (вниз, is_kit=true у компонента) или part_of_kits (вверх), а номер соседнего набора в numbers.article не клади (валидация отклонит пересечение kit_contents/part_of_kits с numbers.article).
21a. Если источники говорят, что с входным артикулом В КОМПЛЕКТЕ поставляется другая деталь со своим номером (например, у гребного винта «Flo-Torq II hub kit 835257K1 (Included)») — это набор: ставь is_kit=true и перечисли в kit_contents и саму основную деталь (article: null, если отдельного номера у неё нет), и входящую деталь с её номером. Факт «в комплекте идёт X» НЕ пиши в description и НЕ оставляй заметкой — его место в kit_contents. И наоборот: если комплект НЕ входит и заказывается отдельно («Order Separate») — это НЕ состав, это нюанс конкретного номера (см. difference-turn).

# Вес и применяемость

22. Вес всегда указывай в килограммах. Фунты, унции и граммы переводи в кг. Если веса нет, weight = null.
22a. Вес — это вес самой OEM-детали по каталожным/производственным данным (OEM-каталог, спецификация, exploded diagram, OEM PDF). НЕ используй shipping weight магазинов и реселлеров (это вес посылки с упаковкой, а не детали) и НЕ используй вес aftermarket-аналогов (Sierra, GLM, Mallory, EMP, Quicksilver-aftermarket и подобных). Если надёжного OEM-веса нет, а есть только вес магазина/реселлера или aftermarket-аналога — weight = null. В evidence указывай, что вес взят именно из OEM-источника.
23. models должен быть null или объектом с text, source_urls и evidence на русском. Каждую подтвержденную применяемость пиши с новой строки.

# Классы техники (vehicle_classes)

24. Определи классы техники, к которой подходит деталь, и положи их слаги в `vehicle_classes`. Главный сигнал — модели применимости (блок `models`): к какой технике относятся найденные модели, те классы и ставь. Отдельных пруфов на классы не нужно — обоснованием служат source_urls и evidence блока `models`.
25. Классов может быть несколько, в том числе разных типов техники: общие детали платформ BRP законно получают `["jetski","snowmobile"]` (двигатели Rotax стоят и в Sea-Doo, и в Ski-Doo) или `["quad","snowmobile"]`. Не выбирай «один главный» — перечисляй все подтверждённые применяемостью.
26. Маркеры брендов и линеек (если модель применимости содержит такой бренд — это его класс):
    - `snowmobile` (снегоходы): Ski-Doo, Lynx, Arctic Cat, Polaris RMK/XC/WideTrak/Switchback;
    - `jetski` (гидроциклы): Sea-Doo, WaveRunner (Yamaha), Kawasaki Jet Ski;
    - `quad` (квадроциклы и мотовездеходы, ATV/SxS/UTV): Can-Am (Outlander, Renegade, Maverick, Defender, Commander), Polaris Sportsman/RZR/Ranger, Honda TRX/Pioneer/Foreman/Rincon;
    - `boat` (катера и лодочные моторы): Mercury, MerCruiser, Quicksilver, Volvo Penta, Evinrude, Johnson, OMC, SeaStar, подвесные моторы Suzuki DF / Honda BF / Yamaha F, sterndrive/outboard;
    - `motorcycle` (мотоциклы): Suzuki GSX-R/GSF, Honda CBR, Yamaha YZF/R1/R6, Kawasaki Ninja;
    - `auto` (автомобили): легковые Audi, Land Rover, Mercedes-Benz и т.п.
27. Если применяемость определить не удалось — `vehicle_classes: []` (run уйдёт на ручное ревью, это нормально). Не угадывай класс по одному только бренду-корпорации: BRP сам по себе класс не определяет (делает гидроциклы, снегоходы и квадры) — смотри на модельный ряд.
